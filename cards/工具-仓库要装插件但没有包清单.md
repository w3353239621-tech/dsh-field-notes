# 工具-仓库要「装插件」但没有包清单

> **触发**：给一个 github.com 仓库地址说「安装插件」/「装最新版」/「把这个仓库装上」，但仓库里没有可安装的包
> **锚点**：`github.com`、`package.json`、`cordis.patch.yml`、`dsh.bundle.patch`、`install`、`AGENTS.md`
> **验证**：新会话系统提示里出现 `Instructions from: ~/.dsh/AGENTS.md`；体检脚本报「0 张卡」而不是「找不到卡库目录」

## 首选

先看清单，别先 clone：

```bash
curl -s "https://api.github.com/repos/<owner>/<repo>/git/trees/main?recursive=1"
# 本机 curl 不通时：用 MCP web_fetch 抓这个 URL（见卡「工具-本机连不上外网」）
```

`package.json` 里有 `dsh.bundle.patch` + `dsh.client` → 真插件，走插件管理器；**两者都没有 → 不是插件**，读 README 的安装段，按「写指令文件 + 建目录」手工装。

## 被挡时

- README 里找「给负责安装的 agent」那一节，通常已写死两件事：全局钩子、工作区目录。
- 只看关键词也能定性：`SKILL.md` → 技能；`procedures/` + `AGENTS.md` → 纯文件约定。

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| 直接当插件装 | 仓库无 `package.json`，插件管理器没有入口可挂 |
| clone 下来再 `pnpm add` | 同上：没有可 link 的包，`dsh.profile.bundles` 也加不进去 |

## 注意

- DSH 指令链顺序：`$DSH_HOME/AGENTS.md` → `<agentsHome>/AGENTS.md` → 工作区 `AGENTS.md` / `CLAUDE.md`。机制写全局，数据（卡）按工作区。
- 判据是「新会话的上下文里真的出现了那段文字」，不是「文件写成功」。

证据：2026-10-25 装 DSH-agent-procedures v0.4.0（commit `caa3e86`）
