# 模型-千帆闲时折扣与套餐选型

> **触发**：判断「夜里跑任务省不省」「哪个模型夜间便宜」「月用量要不要买套餐」
> **锚点**：闲时折扣、夜享 Tokens、22:00-08:00、V4.1-Flash、1 Token 抵 5
> **验证**：`node scripts/token-audit.mjs` 的「闲时段占调用/token」两行，以及按模型的 token 分布

## 首选

1. **先看当期活动页，别信旧文章**：<https://cloud.baidu.com/product/codingplan.html> 顶部「闲时折扣」那行。2026-11-14 核对到的原文是：
   > 闲时折扣上线：调用享2折！限时活动！DeepSeek-V4.1-Flash、DeepSeek-V4-Pro-0813、GLM-5.3 模型每日 22:00-次日 8:00 享 2 折
2. 折后含义：个人版「1 Token 抵 5 Tokens」，即套餐额度在闲时等效 ×5。
3. 用审计脚本量化你能吃到多少：`node scripts/token-audit.mjs --night-start 22 --night-end 8`，看「闲时段占调用 / 占 token」。

## 已知会变的两件事（每次都重核对）

- **起点**：2026-08 的活动是 **21:00**–08:00，2026-11 已改成 **22:00**–08:00。差 1 小时，21 点那个小时是不打折的。
- **名单**：2026-08 是 GLM-5.2 / V4-Flash-0731 / V4-Pro / V4-Flash-0423；2026-11 是 V4.1-Flash / V4-Pro-0813 / GLM-5.3。页面只写家族名（V4.1-Flash），**没点名 1017 这类日期快照**，用前先小额试一次看积分扣减，别假设它在名单里。

## 实测基线（2026-10-21 → 11-14，42.5k 次调用）

| 口径 | 调用占比 | token 占比 |
| --- | --- | --- |
| 21:00–08:00（旧规则误算） | 47.4% | 48.6% |
| **22:00–08:00（现行规则）** | **39.6%** | **40.5%** |

结论：按旧规则会高估 7.8 个百分点（21 点那 3,370 次调用全部按全价），做套餐容量测算时必须用现行窗口。

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| 拿 8 月那篇「夜享 Tokens 21:00 起」当现行规则 | 11 月已改 22:00 起，且名单换了，直接错 8 个百分点 |
| 假设 `deepseek-v4.1-flash-1017` 自动享受 2 折 | 页面只列家族名，快照是否在内未写明；先小额验证 |
| 把「夜间 2 折」当省钱的**主**杠杆 | 你的 token 有 94% 是缓存重读，真正的大头是每次带多少上下文和每天调多少次 |

证据：2026-11-14 建立（套餐选型 + 第 1 步夜跑排班）
