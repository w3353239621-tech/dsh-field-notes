# 脚本-下载大文件卡住和镜像

> **触发**：从 GitHub 下 release 资产/大文件（下载），进度条不动、看起来卡死半小时、脚本跑到一半没反应
> **锚点**：`github.com`、`gh-proxy.com`、`ghfast.top`、`curl.exe`、`sha256`、`ReadWriteTimeout`、`%TEMP%`、`下载`
> **验证**：下完的字节数与 release 资产大小一致，且 `sha256` 对得上

## 首选

镜像 + 多进程断点续传并行，谁先集满用谁：

```powershell
curl.exe -L --retry 3 -C - --max-time 900 -o part1.zip "https://gh-proxy.com/https://github.com/<o>/<r>/releases/download/<tag>/<file>"
curl.exe -L --retry 3 -C - --max-time 900 -o part2.zip "https://ghfast.top/https://github.com/<o>/<r>/releases/download/<tag>/<file>"
```

每 5s 打一次 `part*.zip` 的体积当进度，别等单一进程的静默输出。

## 被挡时

- 直连慢但通时，仍用 `curl.exe -C -`（断点续传），别用包装函数。
- 校验用 release 资产自带的 `sha256`，不要自己算完再猜。

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| pwsh `Install-X` / `GetResponse+CopyTo` 分块下载 | 慢速源下**没有进度输出**，`ReadWriteTimeout` 30s 只切段不退出；3 源 × 5 次循环看着像卡死，临时文件只写到 1.4MB |
| `gh-proxy.net` / `gh.llkk.cc` / `ghgo.xyz` / jsdelivr 取 release 资产 | 全超时（jsdelivr 只服务仓库文件，不服务 release） |

## 注意

- 镜像可用性会变：`gh-proxy.com`、`ghfast.top` 实测可跑（40MB 约 2~3 分钟），换前先小文件试一发。
- DSH 里 `$env:TEMP` 常被改写成 `...\Temp\dsh-XXXXXX`，找遗留临时文件要去 `$env:LOCALAPPDATA\Temp`。
- 进度静默 ≠ 卡死：先看临时文件体积有没有增长再决定重试。

证据：2026-10-27 Pixelorama 包下载，多轮后靠镜像 + 续传跑通
