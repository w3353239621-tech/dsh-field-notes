# 文件-工作区外写不进去（沙箱 Permission denied）

> **触发**：要写 `~/.dsh/` 这类全局位置、或往工作区外复制文件，报 Permission denied
> **锚点**：`Permission denied`、`touch`、`~/.dsh`、`workspace-write`、`danger-full-access`、`AGENTS.md`
> **验证**：`ls -la <目标>` 能看到文件，且 `wc -c` 与源文件字节数一致

## 首选

先在工作区内备好，再**一次**提权写出去（`sandbox_permissions: danger-full-access` + 一句理由，会弹审批）：

```bash
mkdir -p ~/.dsh/agent-procedures
cp -r ./staging/. ~/.dsh/agent-procedures/
cp ./staging/AGENTS.md ~/.dsh/AGENTS.md
```

## 被挡时

- 不提权也能接受时：把机制放工作区 `<工作区>/AGENTS.md`，只在当前区生效。
- 只有「所有工作区共享的机制」值得提权；数据（`procedures/`）本来就该按工作区放。

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| `touch ~/.dsh/x` | `touch: cannot touch '...': Permission denied`（workspace-write 只放行会话工作区） |
| 换 pwsh、换路径写法再试 | 同一层沙箱策略，换壳不换权限 |

## 注意

- 提权是**逐次**的：只对当次调用有效，下一次要重新申请。
- 判据是目标文件字节数，不是命令退出码 —— 复制被截断也会 exit 0。

证据：2026-10-25 装 procedures 时，`~/.dsh/AGENTS.md` 必须提权才写得进去
