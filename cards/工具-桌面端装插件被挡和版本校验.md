# 工具-桌面端装插件被挡和版本校验

> **触发**：给桌面版 DSH 装插件 / 校验插件兼容性 / 改完 bundles 想知道生没生效
> **锚点**：`--profile desktop`、`managed exclusively`、`--dump-config`、`app.asar`、`minimum-release-age`、`skipping profile bundle`、`Incompatible with dsh`、`pnpm add`
> **验证**：`--dump-config` 输出里 `skipping` 计数为 0，且每个目标插件 `- id: <name>` 各出现 1 次（不是「没报错」）

## 首选

装包（CLI 的 plugin 命令对 desktop 一律拒绝，只有 pnpm 和 allow-version 能碰）：

```bash
cd ~/.dsh/profiles/desktop
pnpm add <pkg...> --config.minimum-release-age=0
```

然后在 `~/.dsh/profiles/desktop/package.json` 的 `dsh.profile.bundles` 末尾手工加包名 —— `pnpm add` 只装包，**不会登记 bundles**，不登记等于没装。

校验必须用**桌面应用自带的 rc.5**，不是 TUI 的 CLI：

```bash
node ~/.dsh/dsh-unpacked-verify/dsh/node_modules/@deepseek-ai/dsh/lib/bin.js \
  --profile zz-verify-plugins --dump-config
```

（`_extract_dsh.cjs` / `_scan_dshlib.cjs` 在 workspace 根，按 header 解 asar 到任意可写目录再跑）

## 被挡时

- 插件版本不符：`node <rc.5 bin> plugin --profile <profile> allow-version <name>@<ver> --dsh-version 0.2.1-rc.5 --accept-risk`，落盘在 profile 的 `compatibility.json`，撤销用 `revoke-version`。
- 不想动 live profile：`robocopy <profile> <tmp> /E /XD .plugin-manager`（junction 要 `/XJ`，见 inbox 10-30 那条），在副本上校验。
- 更轻的组合校验（2026-11-11，不用复制 node_modules）：建 `~/.dsh/profiles/<name>-verify/`，只放 `package.json` + `cordis.patch.yml` + `pnpm-workspace.yaml`，`node_modules` 用 `New-Item -ItemType Junction -Target <真 profile>\node_modules` 指过去；`node <cli>\lib\bin.js --profile <name>-verify --dump-config` 输出里出现 `# == <包名>` 段 + `- id: <插件id>` 即登记正确。删镜像先 `cmd /c rmdir <verify>\node_modules` 再 `Remove-Item -Recurse`，别让递归穿过 junction 删到真 profile。

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| `dsh plugin --profile desktop add ...` / `--dump-config` | `error: profile "desktop" is managed exclusively by the Electron application`（`dsh/lib/bin.js` 第 36 行硬拦） |
| 用 `~/.dsh-tui/cli` 的 `bin.js` 校验兼容性 | 那份是 **0.2.1-rc.3**，比桌面应用的 **0.2.1-rc.5** 旧；会被 rc.3 的版本判定误导 |
| 直接 `node D:\DEEPSEEK\resources\app.asar\dsh\...bin.js` | `Cannot find module`：asar 路径 Node 不认，必须先解包 |
| 第一次 `pnpm add` 没带 `--config.minimum-release-age=0`，第二次带上 | `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`：lockfile 里旧条目会被新策略重新核验，**同一 profile 每次 add 参数必须一致** |
| 只解 `@deepseek-ai/dsh*` 就跑去 `--dump-config` | `ERR_MODULE_NOT_FOUND: js-yaml / @deepseek-ai/dsh-launch-environment`：第三方依赖也要一起解 |

## 注意

- 权威版本号三处对齐：`D:\DEEPSEEK\DeepSeek Harness.exe` 的 FileVersion、asar 里 `dsh/node_modules/@deepseek-ai/dsh/package.json`、`runtime/versions.json`。`~/.dsh-tui/cli` 那份**不算**。
- 插件兼容性看 `-id: <pkg>` 在 dump 里出现没有；`skipping profile bundle "xxx": Error: Plugin xxx@y is incompatible with dsh <ver>` 就是被跳过（实测 dsh-skills-manager 0.2.0 全版本要求 0.1.x 客户端 API，rc.5 无解）。
- 改完要重启应用才加载（**0.2.2-rc.1 起不再总是如此，见下条**）：`Get-Process -Name "DeepSeek Harness" | Stop-Process -Force` → `Start-Process "D:\DEEPSEEK\DeepSeek Harness.exe"`，GUI 端口会变（本次 54580 → 49923）。
- 2026-11-11 实测（0.2.2-rc.1 装 dshmarket 1.73.17）：desktop 组合里带 `hmr`（`@deepseek-ai/dsh-hmr`）和 `client-hmr`，`pnpm add` + 手工改 `dsh.profile.bundles` 后**不用重启**——HMR 监听到 profile 变动会热重组。判据不是看日志，是打插件自己挂的路由：`curl -s http://127.0.0.1:<GUI端口>/dsh-market/status` 返回 200 且 `"version":"1.73.17",...[...,]"restart":false` 就说明宿主端已挂载；页面刷新即出新页签（client-hmr 也可能已自动加载）。只有 HMR 报 restart-required 时才需要重启。
- 客户端侧判据（2026-11-11）：带 Cookie 拉 `GET /`，HTML 里 `globalThis["__DSH_BOOT__"]` 的 `entries` 中出现 `{"id":"<包名>","url":"plugins/??<包名>/client.js&rev=..."}` 且该 URL 200 即前端已加载；再看浏览器刷新是否出新标签页。Cookie 可离线铸：`D:\qq-bridge\src\dsh-client.js` 的 `discoverDshSessionCookie(baseUrl)` 返回整串 `name=v1.body.sig`（**字符串**，不是对象），直接塞 `cookie` 头。
- 备份已在 `package.json.bak-plugins-20261102` / `pnpm-lock.yaml.bak-plugins-20261102`。
