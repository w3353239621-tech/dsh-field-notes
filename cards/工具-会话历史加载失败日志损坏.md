# 工具-会话历史加载失败日志损坏

> **触发**：GUI 打开某个会话提示「历史加载失败 / session store log is corrupt」，报错里带 tool/result is outside an open turn
> **锚点**：`outside an open turn`·`session store log is corrupt`·`SessionFormatError`·`session.v4.jsonl.zstd`·`compaction/prune`·`surfaceOp`·`repair-session-log.mjs`
> **验证**：`node verify-session-log.mjs <file>` 三项全过（restoreReleasedV4Artifact + relationships + row admission），退出码 0；修完再开 GUI，历史能滚到底

## 首选

工作区 `_session-repair-20261107/` 里两个脚本，**先停 GUI**：

```bash
node _session-repair-20261107/verify-session-log.mjs <session.v4.jsonl.zstd>
node _session-repair-20261107/repair-session-log.mjs <session.v4.jsonl.zstd> --dry-run
node _session-repair-20261107/repair-session-log.mjs <session.v4.jsonl.zstd> --out=<out.zstd>
node _session-repair-20261107/verify-session-log.mjs <out.zstd>
```

通过后备份原文件再覆盖。详情见 `交接-会话日志损坏排障-20261107.md`。

## 被挡时

- 脚本报「no turn/start after the bad run」：坏行在文件末尾、之后没有新一轮 → 手工在末尾补一个 `turn/start`（seq 顺延）再跑，或直接接受这段历史。
- 只想知道坏在哪：解帧后找 `compaction/prune` 后面紧跟 `tool/result` 且 `surfaceOp.op="replace"` 的连续段，看它前后有没有 `turn/start`。

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| 判成「文件截断」去恢复备份/重建会话 | 帧完整、seq 连续，数据一行没丢，只是顺序非法 |
| 删掉那 42 行 | 替换行删了，被剪的旧结果也没了 —— prune 已把原内容 shadow 掉 |
| 整份重压 | 会丢掉未受影响帧的原字节，体积涨 3 万+，还看不出改了哪里 |

## 注意

- 根因：`dsh-compaction-owner` 在 `agent/status === "idle"` 时做 tier-0 修剪，而 v4 规定 `surfaceOp` 替换行只能在开启的 turn 内（校验器 lib/index.js:619 → :571）。写入不校验、加载才判 corrupt。
- **0.2.5 起的正解**：tier-0 挪到 `compactIfNeeded`（`agent/pre-step`，turn 内、比上一轮结束更早），`ownerPrune` 前置 `ownerTurnOpen()` 守卫（`snapshotEvents()` 倒扫遇 `turn/start`→true、遇 `turn/end`→false）。账本里 prune 的 `trigger` 应是 `pre-step` / `context-overflow`，**见到 `finish-turn` 就是旧法又回来了**。
- 改任何 `surfaceOp` 前记住边界：`compaction/prune` / `compaction/summary` 只校验 `span()`（**turn 外合法**，Live-Compact 的切靠它）；`tool/result` 的 replace 走 `requireTurn()`（**turn 外必崩**）。也不能在 `session/event`(turn/start) 里追加 —— commit 时 `entry.appending` 已置位，会报 `cannot reenter while another append is being published`。
- 「turn 内」到底指哪段（源码依据）：`dsh-agent-loop/lib/index.js` 的 `turn()` 先 `this.session.append("turn/start", { turn })`（:945）再 `await this.preStep(target, { turn, step })`（:956），`preStep()` 里派 `dispatch.waterfall("agent/pre-step", …)`（:909）→ 所以**挂在 `agent/pre-step` 上的逻辑天然在 open turn 内**，这是那股钩子最值得用的地方。
- **别边跑边修**：GUI 内存里是旧 seq，会往同一文件追加打架。
- 应急关 tier-0：profile 里 `pruneRatio: 1` 或 `OWNER_PRUNE_RATIO=1`。
