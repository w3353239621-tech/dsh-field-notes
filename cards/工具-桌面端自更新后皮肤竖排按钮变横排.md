# 工具-桌面端自更新后皮肤竖排按钮变横排

> **触发**：装过皮肤，标题栏右上角三键原本竖排，桌面端更新后变系统原生横排；或要判断"皮肤竖排按钮为什么没了"
> **锚点**：`app.asar` / `titleBarOverlay` / `windowControls` / `desktop-bridge.cjs` / `DSH_DESKTOP_DIR` / `data-windows-titlebar` / `industrial-window-controls`
> **验证**：`Get-FileHash 'D:\DEEPSEEK\resources\app.asar' -Algorithm SHA256` == 适配器输出的 `patchedSha256`，且 `D:\DEEPSEEK\_backups\desktop-caption-<stamp>\app.asar` 存在

## 首选

皮肤只在 `window.dshDesktop.windowControls` 存在时才画竖排三键；桌面端 0.2.2-rc.5 起 preload 不再暴露该桥，改用 lib/main.js 的 `titleBarOverlay` 画原生横排。用上游可选标题栏适配器打补丁：

```
$env:DSH_DESKTOP_DIR = 'D:\DEEPSEEK'      # 桌面端根目录（含 DeepSeek Harness.exe）
node tools\desktop-bridge.cjs check        # 只校验：按 asar 的 sha256 认版本，不改文件
node tools\desktop-bridge.cjs install      # 必须先完全退出桌面端
node tools\desktop-bridge.cjs restore      # 用 _backups 里的 asar 回滚
```

适配器取自皮肤仓库 main 分支的 `tools/desktop-bridge.cjs`；已封装成可双击脚本 `<workspace>\dsh-caption-adapter\install-vertical-caption.cmd`。

## 被挡时

1. `Close Harness before changing the desktop archive.` → 从托盘彻底退出（`Get-Process -Name 'DeepSeek Harness'` 为空）。
2. `check` 报不支持 → 桌面端又换版本，换新版适配器；`install` 会直接拒绝，不会弄坏安装。

| 弯路 | 为什么不通 |
| --- | --- |
| 以为是皮肤版本旧 | 2.4.17→2.4.19 的 client.js 3591 行只差 1 行 CSS；新版反而加 `env(titlebar-area-*)` 给原生按钮让位 |
| 在 asar 里 grep `windowControls` 找桥 | preload-app.cjs / main.js 均 0 次，命中全在 devtools，易误判"桥还在" |
| 双击 `.ps1` 启动脚本 | Windows 关联记事本，只"打开"不运行；中文名 + UTF-8 的 `.cmd` 会被按 GBK 解析成乱码 |

## 注意

- **桌面端每次自动更新都替换 app.asar → 补丁失效、按钮又变横**，重跑 install 即可。更新记录在 `%LOCALAPPDATA%\@deepseek-aidsh-desktop-updater\pending\update-info.json`，装完后 `app.asar` 的 CreationTime 就是更新时间。
- 判桌面端版本别读 exe 属性：解 asar 读根 `package.json`（要用 `require('original-fs')`；头 JSON 在 offset 12，数据基底 = 8 + u32[4]）。

证据：`D:\DEEPSEEK\_backups\desktop-caption-2026-11-19T18-11-37-823Z\`；`dsh-caption-adapter\validation\desktop-bridge.json`；5ec8acd9…d20f69 → 33bb804d…95ccd（rc.5，20056 条目校验）。
