# 脚本-沙箱里管道和权限被挡

> **触发**：在 bash/pwsh 里开子进程、用管道、起交互式 TUI、或往工作区外写文件，一律报权限或管道错误
> **锚点**：`EPERM`、`conpty`、`pipe`、`only core types`、`ConstrainedLanguage`、`danger-full-access`、`MSYS_NO_PATHCONV`、`sandbox`、`沙箱`
> **验证**：命令退出码 0 且产出了东西（文件落盘 / 拿到 stdout），不是靠「没报错」

## 首选

- 需要写 `~/.dsh`、`D:\` 等**工作区外**路径 → 提权到 `danger-full-access`，`workspace-write` 下必被拒。
- bash 里传**以 `/` 开头的参数**（如 `/dsh/node_modules/...`）→ 加 `MSYS_NO_PATHCONV=1`，否则 MSYS 会改写成 `C:\Program Files\Git\...`，脚本静默匹配 0 个。

## 被挡时

- 要跑交互式 TUI（node-pty / conpty）→ 让用户在自己的终端里验，自动化侧只做非交互部分。
- pwsh 在只读沙箱下进 `ConstrainedLanguage`：`[System.IO.File]::`、`Add-Type`、COM、反射全废 → 改用 cmdlet 和核心类型（`[string]`/`[datetime]`/`[regex]`/`[guid]`），`-f` 格式化和属性访问仍可用。

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| 在沙箱里 require node-pty 冒烟测 | `Cannot launch conpty` / `EPERM \\.\pipe\conpty-*`，沙箱禁命名管道 |
| Node `child_process.spawn` 用默认 `stdio:'pipe'` | EPERM；改 `'inherit'`/`'ignore'` 可以，但就拿不到输出 |
| 在 ConstrainedLanguage 里用 .NET 静态方法 | `only core types` 报错，不是语法问题 |

## 注意

- 这是**策略拒绝不是 bug**：不要换别的写法绕过，要么按边界重构，要么明确向用户请求更宽的模式。
- 「管道被禁」和「网不通」是两件事：`git clone` 报 `remote-https: Permission denied` 属于前者。

证据：2026-10-25~27 本机多次踩到，2026-10-28 误建工作区外目录亦属同类边界
