# 任务-长任务阶段交付

> **触发**：长任务做到底（多步改造、批量生成、批量拷库、打包发布），中途被打断、超时、换会话，回头不知道做到哪、哪些验过了
> **锚点**：`todo_write`、`PROGRESS.md`、`.tmp/`、`aborted`、`interrupt`、`checkpoint`、`AGENTS.md`
> **验证**：新会话只读 `PROGRESS.md` 就能接着干，且不重跑已完成的步骤

## 首选

开工先建 `<任务目录>/PROGRESS.md`，固定三栏，**每阶段结束覆盖写**：

```md
## 已完成
- [x] 步骤 —— 产物路径

## 验证（最近一次真跑的命令 + 结果）
- `命令` → exit 0 / 输出摘要

## 下一步
- 步骤
```

阶段按**产物**分，不按时间：审计（结论/清单）→ 实现（diff）→ 验证（命令+输出）→ 交付（文件）。每个阶段都要有一个能贴出来的文件或命令输出。

## 被挡时

- 超过 5 步就开 `todo_write` 让阶段可见；少于 5 步别上这套仪式。
- 被打断后先读 `PROGRESS.md` + `git status`，别从第一条命令重跑。

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| 只在脑子里记进度 | 会话一断就归零，aborted 后常因此返工 |
| 把 todo 当进度存储 | todo 不跨会话、不跨压缩，恢复时看不到 |
| 阶段只写成「审计/实现/验证/交付」口号 | 没有文件=没有恢复入口，等于没拆 |

## 注意

- 交付物的判据是「**下一轮不看聊天记录也能接上**」，不是「我写了个小结」。
- `PROGRESS.md` 覆盖写，不要追加 —— 追加会退化成日志，恢复时还得从头读。
